### Descripción

Un ataque de falsificación de solicitudes en sitios cruzados (Cross Site Request Forgery) se da cuando un adversario obliga a efectuar una solicitud o realizar una acción en nombre de la víctima. Cuando se configura un servidor web para recibir una solicitud de un cliente sin ningún mecanismo para verificar que fue enviada intencionalmente, deja la posibilidad de que un atacante engañe a un cliente para que haga una solicitud no intencional al servidor web y esta será tratada como una solicitud auténtica.

Esto se logra engañando al navegador del usuario para que realice una solicitud a la aplicación mientras se encuentra conectado al sistema. Un posible escenario sería un sitio con un iframe oculto que apunte a la aplicación objetivo. En tal caso, si la víctima visita el sitio fraudulento, el navegador verá el iframe y realizará la solicitud a la aplicación. Si el usuario está actualmente conectado, el navegador incluirá las cookies de sesión del usuario en esta solicitud fraudulenta. Si la aplicación no protege activamente contra este tipo de ataques, un adversario puede desencadenar acciones de la aplicación en nombre del usuario legitimo.

### Impacto

A través de dicha vulnerabilidad, un atacante puede inducir al usuario legitimo de la plataforma a realizar una acción en el aplicativo sin tener conciencia de esto. Si el usuario se encuentra con la sesión iniciada en el navegador y visita una página maliciosa, dicho usuario podría verse en situación de realizar una acción cualquiera en la aplicación de **§[EMPRESA]§**, por ejemplo, §[ACCION GENERADA]§. El atacante envía una solicitud HTTP con información de la aplicación en cuestión y realiza finalmente una acción en nombre del usuario, ya que la sesión continua activa.

### Remediación

Se recomienda el uso de tokens aleatorios para seguir el rastro del usuario a través del flujo de la aplicación. Por ejemplo, un token aleatorio puede pasarse como un campo de formulario oculto. Cuando se presenta el formulario, la aplicación debe comprobar si el token está presente o no. De no es así, la solicitud debe ser descartada. En este escenario, un adversario no podría elaborar una solicitud a la aplicación que contenga un token válido (a menos que existan otras vulnerabilidades que lo revelen) y todas las solicitudes falsas serán identificadas y descartadas por el aplicativo.
