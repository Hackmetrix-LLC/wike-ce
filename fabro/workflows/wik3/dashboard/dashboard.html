🔒 Modo read-only — qué hace exactamente

Cuando safety.read_only_mode: true está activo en la config del engagement (el default para engagements nuevos), el agente respeta una política estricta:

  1. No elimina ni modifica datos pre-existentes durante todo el análisis activo.
  2. Para probar flujos CRUD, crea registros nuevos con marker (wik3-<slug>-<id>) y los registra en notes.jsonl con tag cleanup para limpieza posterior por el cliente.
  3. El hook scope_guard.sh bloquea automáticamente cualquier intento que se le escape al agente:
    • SQL DML/DDL: INSERT, UPDATE, DELETE FROM, DROP, TRUNCATE, ALTER, CREATE, GRANT, REVOKE, RENAME.
    • HTTP destructivo: PUT, PATCH, DELETE; uploads (-T, --upload-file).
    • Shell destructivo: rm -rf, mv, dd if=, mkfs, shred, chmod, chown.

POST queda permitido: login, búsquedas, GraphQL queries y APIs RPC-style lo usan para reads y son necesarios. Si necesitas POST destructivo (mutations GraphQL, etc.), parar el run y desactivar el flag.

Para desactivar (solo si tienes autorización del cliente para destructivo), edita la config y pon:

safety:
  read_only_mode: false

🐛 Burp Suite proxy — chain automático

Estado: —

Con tu Burp abierto, el túnel que ya levantó wik3-hacker.sh manda el tráfico del agente a tu Burp. Cierras Burp → vuelve a salir directo solo.

Lo único por hacer: importar la CA de Burp (una vez). Así tu Burp intercepta el HTTPS del agente sin SSL_VERIFY_FAILED.

⬇ Descargar CA de Burp (.p12)
  1. Burp → Settings → Network → TLS → Import / export CA certificate.
  2. Import → "Certificate and private key in a PKCS#12 keystore".
  3. File: wik3-burp-ca.p12  ·  Password: wik3  → Next → Close.

Bórralo después de importarlo.

➕ Agregar vulnerabilidad manual

Describe la vulnerabilidad con tus propias palabras: dónde está, cómo la encontraste, qué impacto tiene, pasos para reproducir, evidencia. El LLM va a estructurar los campos y los podrás revisar antes de guardar.

Ejemplos: "IDOR en GET /api/orders/{id}: con el token del user A puedo leer la order del user B. Probado con curl, response devuelve email + total".

Revisa y edita los campos. Cuando esté listo, presiona "Guardar" para crearla.

Run

"1 pasada rápida" = recon + análisis activo en una sola pasada (rápido, para chequeos). "N iteraciones completas" = el flujo completo (validate + senior + loop de descubrimiento) hasta N vueltas.

Hint opcional: si ya hay un run previo, el agente NO rehace OSINT/decompile/cloud-enum desde cero — lee el state (recon/, vulns/, queue) y profundiza. El hint dirige dónde focalizar.

Ejemplos: "profundiza en mobile, ignora cloud por ahora" · "el cliente desbloqueó nuestra IP, retomar V-005" · "se autorizó destructivo, intentar SQLi end-to-end".
